# 2. Decoder Technical Specification

## Core Decoding Pipeline

The FVC Decoder is a stateful reconstruction system designed to decode
compressed payloads while preserving temporal dependencies between
consecutive frames.

The decoder combines CPU-side bitstream reconstruction with a hybrid
spatial-temporal GPU architecture.

The decoding process consists of four stages:

1.  **Bitstream Decompression and Parsing**
2.  **Decoupled GPU Memory Initialization**
3.  **Iterative Ping-Pong Reconstruction**
4.  **Temporal State Advancement**

------------------------------------------------------------------------

### 2.1 Bitstream Decompression and Parsing

When a compressed payload is received, the decoder first reverses the
encoder's packing and compression stages on the CPU.

#### Zstandard Decompression

The incoming payload is decompressed using Zstandard, restoring the
dense bit-packed byte array generated by the encoder.

#### Coordinate Restoration

The `BitReader` reads the packed fields and reconstructs the original
block coordinates.

Because the encoder stores coordinates as one-dimensional deltas, the
decoder maintains a running index and reconstructs the original absolute
32-bit `(X, Y)` coordinates for every encoded block.

#### Struct Reconstruction

Packed floating-point values, including contrast, brightness, and
raw-pixel data, are reconstructed from their compact FP16
representations into standard IEEE-754 32-bit floating-point values.

After parsing is complete, the decoder has reconstructed the complete
`HybridCodeData` array.

This array is then uploaded to GPU memory for reconstruction.

------------------------------------------------------------------------

### 2.2 Decoupled Memory Architecture

The decoder maintains three persistent GPU buffers:

  -----------------------------------------------------------------------
  Buffer                              Purpose
  ----------------------------------- -----------------------------------
  `d_prev`                            Read-only reference containing the
                                      finalized previous frame

  `d_buffer_A`                        Iterative reconstruction buffer A

  `d_buffer_B`                        Iterative reconstruction buffer B
  -----------------------------------------------------------------------

Before decoding begins, the finalized previous frame stored in `d_prev`
is copied into both `d_buffer_A` and `d_buffer_B`.

This initialization provides the iterative reconstruction process with a
valid starting image while preserving the previous frame as an immutable
temporal reference.

------------------------------------------------------------------------

### 2.3 Iterative Ping-Pong Execution

Partitioned Iterated Function Systems (PIFS) require multiple
reconstruction passes to converge toward the final image.

The decoder therefore launches the `hybridTemporalDecodeQuadtreeKernel`
in a **three-iteration reconstruction loop**.

The input and output buffers alternate between `d_buffer_A` and
`d_buffer_B` on each iteration.

Conceptually:

``` text
Iteration 1:
d_buffer_A → d_buffer_B

Iteration 2:
d_buffer_B → d_buffer_A

Iteration 3:
d_buffer_A → d_buffer_B
```

After the third iteration, the resolved frame resides in `d_buffer_B`.

------------------------------------------------------------------------

### 2.4 Temporal and Spatial Routing

The decoder enforces different source-buffer rules depending on the
encoded block type.

This separation is critical for preventing temporal information from
being repeatedly transformed during iterative fractal reconstruction.

#### Temporal Blocks

The following block types use the immutable `d_prev` buffer as their
source:

  Code       Representation
  ---------- ----------------
  `0xFFFF`   Temporal Skip
  `0xFFFE`   Motion Vector
  `0xFFFD`   Residual

These blocks never read their temporal reference from the active
ping-pong buffer.

As a result, their reconstruction remains tied to the finalized previous
frame across all three iterations.

This prevents motion offsets and residual corrections from being
repeatedly applied, which could otherwise amplify errors and introduce
temporal noise.

#### Spatial Fractal Blocks

Fractal blocks use the active iterative input buffer, `d_in_iter`, as
their source.

Across the three iterations:

1.  The first pass establishes an initial approximation.
2.  The second pass refines the spatial reconstruction.
3.  The third pass further resolves the fractal transformation.

The iterative process allows contrast, brightness, geometric mapping,
and domain selection to converge toward the target spatial texture.

------------------------------------------------------------------------

### 2.5 State Advancement

After the third decoding iteration completes, the fully reconstructed
frame resides in `d_buffer_B`.

The decoder then copies the resolved frame into `d_prev`.

This operation advances the decoder's temporal state:

``` text
Previous Frame
     │
     ▼
  d_prev
     │
     ├──► d_buffer_A
     │
     └──► d_buffer_B
             │
             ▼
     3 Iterative Passes
             │
             ▼
       Final Frame
             │
             ▼
          d_prev
```

The resulting frame becomes the immutable temporal reference for the
next encoded payload.

------------------------------------------------------------------------

## 4. Key Architectural Properties

The FVC architecture is built around several core design principles:

-   **GPU-accelerated spatial search** for computationally expensive
    fractal matching.
-   **Hierarchical quadtree evaluation** to avoid unnecessary
    fine-grained searches.
-   **Temporal reuse** through skips, motion vectors, and residual
    representations.
-   **Adaptive representation selection** between fractal and residual
    encoding.
-   **Exact raw-pixel fallback** for regions that cannot be safely
    represented by compact residuals.
-   **Delta-coordinate encoding** to reduce spatial metadata overhead.
-   **Bit-level packing** for heterogeneous variable-width fields.
-   **Zstandard compression** for final payload reduction.
-   **Immutable temporal references** during decoder iterations.
-   **Ping-pong GPU buffers** for iterative PIFS convergence.
-   **Explicit separation of temporal and spatial reconstruction paths**
    to prevent error accumulation.
